# Durable private acquisition scheduling

`./scheduler` exports `AcquisitionScheduler`, using the pinned Evidence persistence SDK on a dedicated discovery operational database. Never connect it to another engine's operational database. Apply the SDK migration with a privileged migration identity; the runtime driver must use a separate restricted login granted the runtime role. A trusted host authenticates Context, derives its clock/purpose and owns the Database and mandatory outcome-verifier implementation. Diagnostic strings, source policies and lease tokens are not authentication. There is no raw HTTP endpoint or built-in worker daemon.

A listed human owner creates an explicitly bounded collection. Listed service/agent workers with `discovery:acquire` may lease one due item with an exact expected revision. A lease records the actor, attempt, token and deadline. Leasing is idempotent for lost acknowledgements, but replayed lease metadata grants no execution authority. A separate `consume` transaction changes that lease to running before returning its work description. Consumption is deliberately one-shot: a lost commit acknowledgement requires loading/reconciling state, never repeating I/O on a replayed permit. The host worker must honor these semantics, run the approved capture boundary and quarantine captured bytes.

The scheduler commits collection revisions, audit history and minimal change outbox events transactionally. A completion needs a mandatory verified durable receipt for the exact capture or no-capture outcome. There is no permissive verifier default. The verifier is bounded, receives cancellation and must return exactly true; provider diagnostics are redacted. Receipt references retain their exact kind/ID/revision in the lease, and byte digests/coverage remain in the collection attempt. Only metadata is stored here; captured bytes belong in the evidence engine. Completed attempts do not inflate unique-edition counts.

Expired unconsumed leases become explicit failures because no work description was issued. Expired consumed leases become `reconcile`, keep their attempt started and continue occupying concurrency capacity. They are never automatically retried. The original worker or a listed human owner can resolve them through a verified capture/no-capture receipt. Human pause prevents new leasing and consumption; it cannot recall already consumed work, and completion/reconciliation remains possible while paused. Failed attempts retain the collection refresh cooldown. The state supports up to 1000 items and 10000 retained attempts per collection; archive/rollover requires future host tooling rather than silent history deletion.

The verifier must bind its receipt to the supplied scope, collection/attempt/item, policy, URL, outcome and source digest. It is a trusted integration boundary and must consult durable upstream state, not accept caller strings as proof. Receipt verification is a bounded observation; this adapter does not claim distributed atomic permission fencing or revocation across services. Deployment transaction timeouts and cancellation must accommodate its bounded verifier. A noncooperating verifier is not forcibly terminated, so deployment resource bounds still apply.

Tests execute real migrations, restricted runtime roles, transactional commands, competing revisions, audit/outbox, loss after commit, rollback and a filesystem-backed database reopen. PGlite does not establish independent wire-session contention, runtime network login setup, deployed worker correctness, crash recovery against a real evidence service, or live qualification. No scheduled host process, catalog crawler, outbound mail, publication or real research import is started by this library.
